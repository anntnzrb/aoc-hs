# 2016

Per-day learning log: ideas, surprises, measurements.

Measurements recorded on host `oulu` (13th Gen Intel Core i7-1355U, Linux 7.2.8 x86_64, pinned to P-core 0) using GHC 9.10.3 (GHC2024, cabal `-O1`). Work represents deterministic user-space CPU instruction counts (`perf stat -e instructions:u`) after subtracting an empty-input run, measured across five interleaved pairs. Wall time is the median elapsed duration across runs (10 runs by default; 3 runs for workloads exceeding 1 s) executed under `taskset`.

## Day 01: Coordinate Navigation and Revisit Detection

- Key idea: Parse turns and step counts into directional vectors. Part 1 folds orientation and coordinate displacements from the origin to compute Manhattan distance. Part 2 tracks intermediate coordinates along each path segment in a `Set`, halting at the first revisited position.
- Surprise or lesson: Storing intermediate block coordinates rather than just segment endpoints is necessary for revisit detection; routes without revisits safely yield a fallback placeholder.
- Primary measurement: 2.49 M instructions (2,488,306 work_med), 2.14 ms (2,140 µs wall_med), RSS 6,924 KiB.

## Day 02: Keypad Coordinate Navigation

- Key idea: Map keypad buttons to coordinates and fold directional movements over the layout, clamping invalid steps by rejecting moves outside the coordinate map. Part 1 uses a 3x3 square keypad; part 2 uses a diamond-shaped layout.
- Surprise or lesson: Representing keypad layouts as `Map (Int, Int) Char` makes boundary checks implicit via lookup failure, keeping directional step evaluation total without custom bounds logic.
- Primary measurement: 3.65 M instructions (3,652,773 work_med), 2.90 ms (2,902 µs wall_med), RSS 9,232 KiB.

## Day 03: Triangle Inequality Validation

- Key idea: Validate triplets of side lengths using the triangle inequality `a + b > c && a + c > b && b + c > a`. Part 1 tests rows directly; part 2 groups consecutive three-row blocks, transposing columns into vertical triplets.
- Surprise or lesson: Direct inequality tests avoid sorting side lengths. Unfolding three-row blocks safely produces an empty group without crashing on uneven trailing inputs.
- Primary measurement: 25.64 M instructions (25,637,479 work_med), 4.69 ms (4,694 µs wall_med), RSS 10,552 KiB.

## Day 04: Character Frequency Checksums and Caesar Cipher

- Key idea: Validate sector checksums by sorting character frequency maps (descending by frequency, breaking ties alphabetically) and comparing the top five characters against the written checksum. Part 2 applies modular Caesar shifts to sector names to locate target storage.
- Surprise or lesson: Alphabet frequency maps are bounded to at most 26 entries, keeping sorting and ranking overhead negligible.
- Primary measurement: 39.21 M instructions (39,214,896 work_med), 6.48 ms (6,478 µs wall_med), RSS 11,056 KiB.

## Day 05: MD5 Digest Search

- Key idea: Increment sequential indices appended to the salt, computing MD5 digests with 20 leading zero bits. Part 1 takes sixth hex characters sequentially; part 2 uses sixth characters as position indices (0..7) and seventh characters as values, filling positions until all eight slots are determined.
- Surprise or lesson: Refactoring to an in-place decimal `ByteString` counter and testing raw nibble values via `hexNibbles` without full hex encoding reduced instructions by 36%.
- Primary measurement: 37.05 B instructions (37,047,471,261 work_med), 3.10 s (3,096,192 µs wall_med), 3 timing runs, RSS 12,984 KiB.

## Day 06: Column Frequency Analysis

- Key idea: Transpose character columns across equal-width input rows. Build frequency maps for each position; part 1 picks the maximum frequency character per column, and part 2 picks the minimum frequency character.
- Surprise or lesson: A single fold over column frequencies extracts both the most and least common characters simultaneously, processing both parts in one pass over the transposed matrix.
- Primary measurement: 6.52 M instructions (6,516,711 work_med), 4.43 ms (4,427 µs wall_med), RSS 10,384 KiB.

## Day 07: Palindromic String Pattern Matching

- Key idea: Parse bracketed strings into supernet (unbracketed) and hypernet (bracketed) segments. Part 1 checks for 4-character autonomous palindromes (ABBA with distinct adjacent characters) in supernets while forbidding them in hypernets. Part 2 extracts 3-character palindromes (ABA) outside brackets and intersects their inverted BAB patterns with bracketed contents.
- Surprise or lesson: Collecting 3-character candidate patterns into bounded sets turns overlapping substring matching and cross-segment verification into efficient set operations.
- Primary measurement: 95.40 M instructions (95,395,512 work_med), 13.99 ms (13,991 µs wall_med), RSS 12,344 KiB.

## Day 08: Display Grid Simulation and Glyph Recognition

- Key idea: Simulate a 50x6 pixel grid as a `Set (Int, Int)` of lit coordinates under rectangular fill and wrapped row/column shift operations. Part 1 reports the lit set size; part 2 slices the screen into 5x6 subgrids and matches against a pre-defined pixel font.
- Surprise or lesson: Representing active pixels as a sparse set ensures idempotent additions during overlapping rectangle fills and makes rotations simple coordinate mappings.
- Primary measurement: 6.77 M instructions (6,768,106 work_med), 4.34 ms (4,339 µs wall_med), RSS 9,672 KiB.

## Day 09: Recursive Decompression Expansion

- Key idea: Parse marker tokens `(length x count)`. Part 1 accumulates decompressed lengths by multiplying marker payload length by repeat count without recursing into payloads. Part 2 expands nested markers recursively, computing total size purely through arithmetic.
- Surprise or lesson: Avoiding buffer materialization and tracking lengths via `Natural` allows computing astronomical decompressed sizes in linear time relative to compressed input length and nesting depth.
- Primary measurement: 19.78 M instructions (19,776,357 work_med), 5.38 ms (5,379 µs wall_med), RSS 10,424 KiB.

## Day 10: Routing Network Simulation

- Key idea: Simulate chip routing among bots and output bins. A persistent map holds single waiting chips; bots receiving two chips dispatch lower and higher chips to destination queues. Part 1 identifies the bot comparing target values; part 2 computes the product of chips placed in output bins 0, 1, and 2.
- Surprise or lesson: A purely functional queue (`Seq`) and state map simulate asynchronous handoffs deterministically, requiring no complex scheduling.
- Primary measurement: 2.97 M instructions (2,966,957 work_med), 3.25 ms (3,254 µs wall_med), RSS 8,200 KiB.

## Day 11: Elevator State BFS and Symmetry Reduction

- Key idea: Search shortest elevator transit paths bringing all generators and microchips to the fourth floor using breadth-first search. Quotient out element identity symmetries by sorting `(generator_floor, chip_floor)` pairs into canonical order.
- Surprise or lesson: Canonical pair states fit packed integer keys, enabling `IntSet` traversal via `AoC.Search` and bitmask safety checks; state reduction shrinks an intractable graph into a manageable space.
- Primary measurement: 2.24 B instructions (2,239,085,221 work_med), 238.22 ms (238,225 µs wall_med), RSS 11,636 KiB.

## Day 12: Basic Assembunny Bytecode Execution

- Key idea: Interpret Assembunny bytecode (copy, inc, dec, jnz) across registers `a` through `d`. Part 1 initializes register `c` to 0; part 2 initializes register `c` to 1.
- Surprise or lesson: Shared loop acceleration in `AoC.Assembunny` detects and collapses linear addition and multiplication loops, reducing runtime from ≈0.58 s to ≈5 ms (2.65 ms wall_med).
- Primary measurement: 1.65 M instructions (1,653,265 work_med), 2.65 ms (2,646 µs wall_med), RSS 6,852 KiB.

## Day 13: Procedural Maze Traversal

- Key idea: Determine wall versus open coordinates on the fly via the bit parity of `x*x + 3*x + 2*x*y + y + y*y + salt`. Use `AoC.Search.breadthFirstLayers` and `AoC.Grid.orthogonal` to explore reachable coordinates.
- Surprise or lesson: Generating lazy BFS layers allows reusing the single traversal to both locate the target coordinate and count all locations reachable within 50 steps.
- Primary measurement: 3.75 M instructions (3,750,940 work_med), 2.93 ms (2,933 µs wall_med), RSS 6,676 KiB.

## Day 14: Key Stretching and Windowed MD5 Search

- Key idea: Generate lazy streams of MD5 digests (1 round for part 1, 2017 rounds for part 2). Detect keys where the first triplet character matches a quintuple within the subsequent 1000 digests, finding the 64th valid key index.
- Surprise or lesson: Part 2 requires 47,276,343 MD5 compressions. Profiling shows ≈60% of runtime in C MD5 compression and ≈27% in hex encoding; runtime stays at ≈6.36 s, reaching the hardware limit of safe ByteString MD5 hashing.
- Primary measurement: 69.21 B instructions (69,212,208,373 work_med), 6.36 s (6,358,932 µs wall_med), 3 timing runs, RSS 30,684 KiB.

## Day 15: Modular Disc Alignment

- Key idea: Solve disc alignment timing where disc `i` with `n_i` positions starting at `p_i` aligns at `(t + i + p_i) mod n_i == 0`. Fold discs by stepping candidate time by the current period (`lcm`) to satisfy each disc successively.
- Surprise or lesson: Incremental period stepping (`foldlM align`) solves simultaneous modular congruences directly without requiring external Chinese Remainder Theorem solvers.
- Primary measurement: 92.35 k instructions (92,353 work_med), 2.38 ms (2,376 µs wall_med), RSS 6,408 KiB.

## Day 16: Dragon Curve Checksum via Prefix Parity

- Key idea: Generate binary data via modified dragon curve mirroring (`a 0 b'`) and compute iterative pairwise checksums until length is odd.
- Surprise or lesson: Computing checksum bits directly from dragon curve prefix parities without expanding the disk buffer in memory dropped runtime from ≈0.13 s to ≈2 ms (2.36 ms wall_med, 96.04 k instructions), handling a 35.6 MB virtual disk in logarithmic time.
- Primary measurement: 96.04 k instructions (96,041 work_med), 2.36 ms (2,361 µs wall_med), RSS 6,164 KiB.

## Day 17: Hash-Directed Grid Pathfinding

- Key idea: BFS on a 4x4 coordinate grid where open doors are determined by the first four hex characters of `MD5(passcode <> path)`. Reaching the destination corner terminates paths; part 1 returns the shortest path, part 2 returns the maximum path length.
- Surprise or lesson: Maintaining incremental `Crypto.Hash.MD5.Ctx` contexts and reversed byte paths avoided rehashing the passcode prefix at every step, reducing instructions by 57%.
- Primary measurement: 89.07 M instructions (89,071,196 work_med), 13.97 ms (13,974 µs wall_med), RSS 12,264 KiB.

## Day 18: Cellular Automaton Row Bitmasks

- Key idea: Generate cellular automaton rows where a tile is trapped if its parent left and right neighbours differ (`L /= R`). Count safe tiles over 40 rows (part 1) and 400,000 rows (part 2).
- Surprise or lesson: Encoding rows as arbitrary-precision `Integer` bitmasks and transitioning rows via `(shiftL bits 1 `xor` shiftR bits 1) .&. mask` with `popCount` safe counting dropped runtime from ≈0.7 s to ≈26 ms.
- Primary measurement: 381.16 M instructions (381,161,054 work_med), 26.66 ms (26,664 µs wall_med), RSS 10,484 KiB.

## Day 19: Josephus Elimination Recurrences

- Key idea: Solve token-passing circle elimination. Part 1 removes adjacent players (standard Josephus problem). Part 2 removes the player directly across the circle.
- Surprise or lesson: Part 2 was solved in closed form between powers of three (`3^k`), replacing linear circle simulation with a logarithmic formula and reducing work to 33.97 k instructions (2.35 ms wall_med).
- Primary measurement: 33.97 k instructions (33,974 work_med), 2.35 ms (2,352 µs wall_med), RSS 6,120 KiB.

## Day 20: Address Range Interval Merging

- Key idea: Parse inclusive blocked 32-bit address intervals `[low, high]` and sort them. Part 1 advances through blocked ranges to find the first uncovered address. Part 2 sums uncovered address gaps up to `2^32 - 1`.
- Surprise or lesson: Sorting and merging intervals handles the 32-bit address space in O(n log n) time and O(n) memory without allocating bitmaps or iterating addresses.
- Primary measurement: 12.12 M instructions (12,121,429 work_med), 5.12 ms (5,118 µs wall_med), RSS 10,528 KiB.

## Day 21: Scrambling Transformation Inversion

- Key idea: Apply string scrambling operations (swaps, rotations, reversals, moves) sequentially. Part 1 runs operations forward on an 8-character string. Part 2 inverts operations in reverse order.
- Surprise or lesson: Inverting index-dependent rotations by exhaustively testing all 8 possible rotations keeps inverse operations total and verified without manual reverse-mapping lookup tables.
- Primary measurement: 919.82 k instructions (919,815 work_med), 2.80 ms (2,804 µs wall_med), RSS 7,056 KiB.

## Day 22: Storage Cluster Sliding Tile Search

- Key idea: Part 1 counts viable node pairs where used capacity fits target availability. Part 2 models data movement as a sliding tile puzzle: move the single empty node around large barriers to maneuver the target data node to the origin.
- Surprise or lesson: Verifying disk capacity invariants confirms only empty-slot swaps are valid; compact integer state encoding and cached orthogonal adjacency dropped runtime from ≈1.2 s to ≈0.11 s (114.27 ms wall_med).
- Primary measurement: 1.03 B instructions (1,029,158,288 work_med), 114.27 ms (114,265 µs wall_med), RSS 13,872 KiB.

## Day 23: Self-Modifying Bytecode Execution

- Key idea: Execute Assembunny bytecode with the `tgl` instruction, which dynamically toggles target instructions between copy/jump and inc/dec. Part 1 starts with register `a` = 7; part 2 starts with register `a` = 12.
- Surprise or lesson: Shared `acceleratedStep` in `AoC.Assembunny` safely collapses multiplication and addition loops even within self-modifying code, executing part 2 in 2.52 ms (1.02 M instructions).
- Primary measurement: 1.02 M instructions (1,024,970 work_med), 2.52 ms (2,522 µs wall_med), RSS 6,724 KiB.

## Day 24: Grid Graph All-Pairs Shortest Path and TSP

- Key idea: Find the shortest path visiting all numbered points in an open grid maze. Precompute all-pairs shortest path distances between points using BFS with `AoC.Search` and `AoC.Grid`. Compute minimal tour lengths via Held-Karp dynamic programming over `(visited_mask, current_node)`.
- Surprise or lesson: Decomposing the search into an all-pairs distance precomputation and a bitmask TSP over `k <= 8` nodes solves the traversal instantaneously (21.31 ms wall_med).
- Primary measurement: 103.62 M instructions (103,620,853 work_med), 21.31 ms (21,308 µs wall_med), RSS 12,680 KiB.

## Day 25: Clock Signal Cycle Verification

- Key idea: Search for the lowest positive initial value in register `a` that causes Clock Assembunny (`out` instruction) to emit an infinite alternating binary sequence (0, 1, 0, 1, ...). Test candidate seeds sequentially until reaching a repeated machine state.
- Surprise or lesson: Runtime dropped from ≈10.1 s to ≈11 ms (6.73 ms wall_med, 38.39 M instructions) by accelerating non-output arithmetic loops (multiplication and countdown division) while preserving complete state cycle proofs.
- Primary measurement: 38.39 M instructions (38,385,747 work_med), 6.73 ms (6,730 µs wall_med), RSS 10,428 KiB.

## Year themes

- Shared modules extracted:
  - `AoC.Assembunny`: Unified bytecode parsing and execution across three dialects (`Basic`, `SelfModifying`, `Clock`) for Days 12, 23, and 25. Shared loop acceleration (`acceleratedStep`) collapsed arithmetic loops into direct register manipulation, dropping runtimes from seconds to milliseconds while preserving exact machine state.
  - `AoC.MD5`: Common MD5 hashing utilities for Days 05, 14, and 17, providing lowercase hex encoding, repeated stretching (`md5HexRepeated`), and raw nibble extraction (`hexNibbles`).
  - `AoC.Search`: Breadth-first graph traversal providing lazy layer generation (`breadthFirstLayers`), shortest distance finding, and integer-specialized BFS (`shortestIntDistance`) using `Data.IntSet` for Days 11, 13, 22, and 24.
  - `AoC.Grid`: Coordinate lattice adjacency (`orthogonal`, `adjacent`) shared across 2D grid searches in Days 13, 22, and 24.
- What dominated runtime:
  - Cryptographic hashing dominated overall runtime: Day 14 required 6.36 s (69.21 B instructions) due to 47.3 million MD5 compressions during key stretching, and Day 05 required 3.10 s (37.05 B instructions). Together, Days 05 and 14 accounted for over 90% of total year CPU and wall time.
  - State space search in Day 11 (2.24 B instructions, 238.22 ms) and sliding tile search in Day 22 (1.03 B instructions, 114.27 ms) formed the next largest workloads, both kept tractable through canonical state quotients and packed integer keys.
